# TODOS.md 格式參考

此文件為規範化的 `TODOS_zh_TW.md` 格式之共享參考。由 `/ship`（步驟 5.5）與 `/plan-ceo-review`（TODOS.md 更新章節）引用，以確保待辦事項結構的一致性。

---

## 檔案結構

```markdown
# 待辦事項 (TODOS)

## <技能/組件>     ← 例如：## 瀏覽器 (Browse), ## 交付 (Ship), ## 審核 (Review), ## 基礎設施 (Infrastructure)
<項目按優先級排序，P0 在最上方，接著是 P1, P2, P3, P4>

## 已完成
<已完成的項目，並附帶完成標註>
```

**章節規劃**：按技能或組件組織（`## 瀏覽器`, `## 交付`, `## 審核`, `## QA`, `## 回顧`, `## 基礎設施`）。在每個章節內，按優先級排序（P0 置頂）。

---

## 待辦項目格式

每個項目在所屬章節下均為 H3 標題：

```markdown
### <標題>

**內容 (What)**：一行的工作描述。

**原因 (Why)**：解決的具體問題或解鎖的價值。

**背景 (Context)**：充足的細節，以便三個月後接手的人理解動機、當前狀態與起點。

**工作量 (Effort)**：S / M / L / XL
**優先級 (Priority)**：P0 / P1 / P2 / P3 / P4
**依賴於 (Depends on)**：<前置條件，或「無」>
```

**必要欄位**：內容、原因、背景、工作量、優先級
**選填欄位**：依賴於、阻礙於 (Blocked by)

---

## 優先級定義

- **P0** — 阻礙性：必須在下次發布前完成
- **P1** — 關鍵性：應在此週期內完成
- **P2** — 重要性：當 P0/P1 清理完畢後執行
- **P3** — 錦上添花：在獲得採用率/使用數據後重新審視
- **P4** — 未來想法：不錯的點子，但無急迫性

---

## 已完成項目格式

當項目完成時，將其移動至 `## 已完成` 章節，保留其原始內容並在結尾追加：

```markdown
**完成於：** vX.Y.Z (YYYY-MM-DD)
```

## 完整性原則 — 沸騰湖水 (Boil the Lake)

AI 輔助編程使完整性的邊際成本接近於零。當你提供選項時：

- 如果選項 A 是完整實作（完全對等、所有邊際情況、100% 覆蓋率），而選項 B 是節省少量工作量的捷徑 —— **始終建議 A**。在使用 CC+gstack 的情況下，80 行與 150 行之間的差異是微不足道的。當「完整」僅需多花幾分鐘時，「夠好就好」是錯誤的直覺。
- **湖泊 vs. 海洋：** 「湖泊」是可以煮沸的 —— 例如模組的 100% 測試覆蓋率、完整的功能實作、處理所有邊際情況、完整的錯誤路徑。「海洋」則不然 —— 例如從頭重寫整個系統、在你不受控的依賴項中新增功能、跨越多個季度的 platform 遷移。建議煮沸湖泊。將海洋標記為超出範疇。
- **估算工作量時**，始終顯示兩種尺度：人類團隊時間與 CC+gstack 時間。壓縮率隨任務類型而異 —— 請參考此對照表：

| 任務類型 | 人類團隊 | CC+gstack | 壓縮率 |
|-----------|-----------|-----------|-------------|
| 樣板代碼 / 腳手架 | 2 天 | 15 分鐘 | ~100x |
| 撰寫測試 | 1 天 | 15 分鐘 | ~50x |
| 功能實作 | 1 週 | 30 分鐘 | ~30x |
| Bug 修復 + 回歸測試 | 4 小時 | 15 分鐘 | ~20x |
| 架構 / 設計 | 2 天 | 4 小時 | ~5x |
| 研究 / 探索 | 1 天 | 3 小時 | ~3x |

- 此原則適用於測試覆蓋率、錯誤處理、文件撰寫、邊際情況以及功能完整性。不要為了「節省時間」而跳過最後 10% —— 有了 AI，那 10% 僅需幾秒鐘。

# 設置瀏覽器 Cookie (Setup Browser Cookies)

將您真實 Chromium 瀏覽器中已登入的會話匯入無頭瀏覽器會話中。

## 運作原理

1. 尋找瀏覽器二進位檔
2. 執行 `cookie-import-browser` 以偵測已安裝的瀏覽器並開啟選擇器 UI
3. 用戶在瀏覽器中選擇要匯入哪些 Cookie 域名
4. Cookie 會被解密並載入 Playwright 會話中

## 步驟

### 1. 尋找瀏覽器二進位檔

## 設置 (在執行任何瀏覽指令前，請先執行此檢查)

```bash
_ROOT=$(git rev-parse --show-toplevel 2>/dev/null)
B=""
[ -n "$_ROOT" ] && [ -x "$_ROOT/.claude/skills/gstack/browse/dist/browse" ] && B="$_ROOT/.claude/skills/gstack/browse/dist/browse"
[ -z "$B" ] && B=~/.claude/skills/gstack/browse/dist/browse
if [ -x "$B" ]; then
  echo "READY: $B"
else
  echo "NEEDS_SETUP"
fi
```

如果顯示 `NEEDS_SETUP`：
1. 告訴用戶：「gstack browse 需要一次性建置（約 10 秒）。是否繼續？」然後停止並等待。
2. 執行：`cd <SKILL_DIR> && ./setup`
3. 如果未安裝 `bun`：`curl -fsSL https://bun.sh/install | bash`

### 2. 開啟 Cookie 選擇器

```bash
$B cookie-import-browser
```

這會自動偵測已安裝的 Chromium 瀏覽器（Comet, Chrome, Arc, Brave, Edge），並在您的預設瀏覽器中開啟一個互動式選擇器 UI，您可以在其中：
- 在已安裝的瀏覽器之間切換
- 搜尋域名
- 點擊「+」號匯入某個域名的 Cookie
- 點擊垃圾桶圖示移除已匯入的 Cookie

告訴用戶：**「Cookie 選擇器已開啟 —— 請在瀏覽器中選擇您想要匯入的域名，完成後告訴我。」**

### 3. 直接匯入 (替代方案)

若用戶直接指定了域名（例如 `/setup-browser-cookies github.com`），則跳過 UI：

```bash
$B cookie-import-browser comet --domain github.com
```

若有指定，請將 `comet` 替換為對應的瀏覽器。

### 4. 驗證

當用戶確認完成後：

```bash
$B cookies
```

向用戶展示已匯入 Cookie 的摘要（各域名的計數）。

## 注意事項

- 每個瀏覽器的首次匯入可能會觸發 macOS 金鑰鏈 (Keychain) 對話框 —— 請點擊「允許 (Allow)」或「始終允許 (Always Allow)」
- Cookie 選擇器由瀏覽伺服器在同一個連接埠提供服務（無須額外進程）
- UI 中僅顯示域名與 Cookie 計數 —— 絕不洩露 Cookie 的具體值
- 瀏覽會話會在指令之間持久化 Cookie，因此匯入後可立即生效
